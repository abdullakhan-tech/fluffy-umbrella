# Contributing

## Workflow
1. Open an issue describing the problem or proposed change.
2. Keep pull requests focused and explain user-visible behaviour.
3. Update documentation and tests with code changes.
4. Never include secrets, personal data, or generated credentials.
5. Include screenshots for substantial UI changes where practical.

## Local setup
Follow `README.md` and `DEPLOYMENT.md`.

## Pull request checklist
- [ ] Scope and limitations are clear.
- [ ] Mobile and desktop behaviour considered.
- [ ] Keyboard and reduced-motion behaviour considered.
- [ ] Tests run, or untested areas disclosed.
- [ ] Documentation updated.
- [ ] No secrets or private user data included.
