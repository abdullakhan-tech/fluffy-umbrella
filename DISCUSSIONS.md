# GitHub Discussions Guide

GitHub Discussions is enabled for this repository. Use Discussions for open-ended design conversations and community questions; use Issues for actionable, trackable work and bug reports.

## Suggested categories
Create or confirm these categories in the repository's **Settings → General → Features → Discussions → Categories** area:

1. **Announcements** — maintainer updates and release notes (maintainers only).
2. **Ideas & Feature Requests** — proposals that need community feedback before becoming issues.
3. **Questions & Help** — setup, Termux, Windows, API configuration, and usage questions.
4. **Show and Tell** — demos, screenshots, and integrations (never post secrets or personal data).
5. **Architecture & Roadmap** — design trade-offs, agent behavior, memory, providers, and platform direction.

Category creation and discussion posting are GitHub repository actions; this markdown file documents the workflow and does not create categories or posts automatically.

## Discussion template: feature idea
**Problem:** What user problem should Zaythar solve?

**Proposed behavior:** What should happen?

**Platforms:** Android/Termux, Windows, browser, or all?

**Privacy and permissions:** What data or device permissions are needed?

**Alternatives:** What other approaches were considered?

**Acceptance criteria:** How will we know the idea is complete?

## When to create an Issue
After a discussion reaches a clear, actionable outcome, open an Issue with scope, acceptance criteria, platform impact, and test expectations. Do not use Discussions as a substitute for bug tracking.
